# LAB4-PP4i: Understand（スキャン済みメタデータで即答） 🔍

## 🎯 このラボの目標

このラボは**PP4i の Understand 機能を体験するオプションメニュー**です。LAB1-PP4i の次に、任意で実施できます（LAB2・LAB3 とは独立しており、実施しなくても、順番を問わず実施しても問題ありません）。

### 🎬 シナリオ

> あなたは、IBM i の基幹システムの保守を**前任者から引き継いだばかり**です。設計書は見当たらず、頼れるのは IBM i 上のオブジェクトだけです。
> そこへ営業部門から依頼が届きます。
> **「得意先マスター（`TOKMSP`）に FAX 番号の項目を追加したい。どこまで直せばいい？」**
>
> 「どのプログラムが `TOKMSP` を使っているのか」を、ソースを 1 本ずつ開いて調べるのは大変です。
> Understand で事前にスキャンしておくと、**Bob が全体像と影響範囲を、その場で答えてくれます。**

### 🌟 このラボで体感できる Understand の価値

| 価値 | 体験するステップ |
|---|---|
| **スキャン 1 回で、以後は「聞くだけ」** — 質問のたびにオブジェクトを調べ直さない | ステップ2 |
| **引き継ぎ・属人化の解消** — 設計書がなくても、アプリ全体の構造が分かる | ステップ4.1 |
| **変更前の影響分析** — 直接参照と、論理ファイル経由の間接参照を見落とさない | ステップ4.2 |
| **着手の迅速化** — 改修対象プログラムの構成・使用ファイル・呼び出し関係がすぐ分かる | ステップ4.3 |
| **リスクと整理対象の可視化** — 古い方式（OPM）や動的 SQL、使われていない資産を洗い出せる | ステップ4.4（オプション） |
| **Bob コインの節約** — 事前スキャンしたメタデータを参照するため、消費が抑えられる（記事の事例） | 「このラボで学んだこと」 |

**所要時間**: 15分  
**難易度**: ★★☆☆☆（初中級）  
**使用モード**: IBM i Developer モード  
**ワークスペース**: Local  
**前提**: LAB1-PP4i を完了していること（`STUDYxx` が複製済み）。LAB2・LAB3 の実施は不要です。Understand が日本語環境に対応済みの環境で実施してください  
**検証バージョン**: IBM Bob Premium Package for i v2.0.0（画面・表構造は今後変更される可能性があります）

## 📚 学習内容

- ✅ Understand のインストール（空ライブラリーの作成と install library の設定）
- ✅ アプリケーションの登録とスキャン
- ✅ Dashboard（Insights / Objects）でのオブジェクト依存関係の確認
- ✅ Understand 用スキルとツールによる、アプリ概要・影響分析・プログラム説明・整理対象の洗い出し

### Understand とは

IBM i のライブラリーを**オブジェクト単位でスキャンし、オブジェクト同士の関係（プログラム呼び出し、ファイル使用、サービスプログラム、SQL 依存、トリガー、制約）をメタデータとして登録**しておく機能です。登録後は、Bob がオブジェクトを調べに行かず、スキャン結果から構造的な質問に答えます。

> ⚠️ **ソースは読みません。** スキャン対象は**コンパイル済みオブジェクト**です。

## ステップ0: 事前準備（1分）

1. **New Task** をクリックして新しいタスクを開始する
2. ワークスペースは **「Local」** のまま
3. **チャットウィンドウ左下**のモード選択が **「IBM i Developer」** になっていることを確認
4. `STUDYxx` にコンパイル済みオブジェクト（`*PGM` / `*FILE`）があることを確認する（`xx` は自分の番号）

```
STUDYxx ライブラリーにあるオブジェクトを、種類（*PGM、*FILE、*SRVPGM）ごとに件数で集計してください。
```

**期待される動作**: Bob が `execute_sql_statement` で `QSYS2.OBJECT_STATISTICS` を実行し、`*PGM` と `*FILE` の件数が表示されます。

> ⚠️ **スキャン対象外のライブラリー**: 名前が `Q` で始まるライブラリー、名前に `SYS` を含むライブラリーはスキャンできません（記事の記載）。`QEOL` は直接使えないため、LAB1 で複製した `STUDYxx` を使います。

---

## ステップ1: Understand のインストール（3分）

### 1.1 メタデータ格納用の空ライブラリーを作る

Understand はスキャン結果を IBM i 上のライブラリーに保存します。**空のライブラリーを新規に作成**します（`UNDxx`、`xx` は各自の番号）。

1. 左のアクティビティバーで **OBJECT BROWSER** を開く
2. **New Library** を選択する
3. 画面上部の入力欄にライブラリー名 `UNDxx`（`xx` は各自の番号）を入力して Enter

> ⚠️ **権限に注意**: install library には必要最小限の権限だけを付けてください。権限を広げると、スキャンしたメタデータ（権限外のオブジェクト情報を含む）が見えてしまう恐れがあります。

### 1.2 install library を設定する

1. **Set install library** を選択し、作成したライブラリー `UNDxx` を入力する
2. 設定画面を閉じる（× ボタン）

> 💡 **設定画面が表示されない場合**: Bob を再起動すると表示されることがあります。

### 1.3 Understand をインストールする

1. チャット入力欄の **Workflow ボタンの横にある Understand ボタン**を押して Dashboard を開く
2. **Overview** で **Install Understand** を選択する
3. 「ライブラリーが空か」の確認が出たら、空であることを確認して**続行**する

**期待される動作**: 必要なオブジェクトが `UNDxx` にインストールされます。

---

## ステップ2: アプリケーションを登録してスキャンする（3分）

### 2.1 アプリケーションを登録する

1. Dashboard の **Applications** タブで **New application**（＋ Add application）を押す
2. 次の項目を入力して登録する

| 項目 | 入力例 |
|---|---|
| Display name | `STUDYxx` |
| Description | `得意先・受注管理（引き継ぎ案件）` |
| Library | `STUDYxx`（自分の番号。複数選択可） |

### 2.2 スキャンを実行する

登録したアプリケーションの **Scan** を押します。

**期待される動作**: スキャンが完了し、アプリケーションが **Scanned** になります。

> 🌟 **ポイント**: スキャンは**最初の 1 回だけ**です。以降の質問は、すべてこのスキャン結果から答えます。質問のたびにオブジェクトを調べ直す必要はありません。
>
> 💡 スキャン中も、ほかのタブは使えます。**Messages** タブに、解決できなかった参照などの診断情報が出ます。

## ステップ3: Dashboard で全体を眺める（2分）

1. **Insights** タブで、オブジェクト種別ごとの件数、最も多く参照されているオブジェクト、動的 SQL の使用状況などを確認する
2. **Objects** タブで `TOKMSP`（得意先マスター）を選ぶ
3. 「このオブジェクトが使うもの」と「このオブジェクトを使うもの」を確認する

**期待される動作**: ソースを 1 本も開かずに、`TOKMSP` が**どのプログラム・論理ファイルから使われているか**がクリックだけで分かります。

> 💡 ここで見えた関係を、次のステップでは Bob に**言葉で聞いて**答えてもらいます。

## ステップ4: シナリオに沿って Bob に聞く（5分）

> 💡 **自動承認**: チャット欄の権限設定に Understand の自動承認ボタンがあります。毎回の承認を省略したい場合に使えます。
>
> 💡 **使われたツールの確認方法**: チャットの実行履歴に `understand_*` ツールの呼び出しが並びます。ソースを開く `read_member` ではなく、`understand_*` が使われていることに注目してください。

### 4.1 引き継いだシステムの全体像をつかむ

**場面**: 設計書がありません。まず、何があるシステムなのかを知りたい。

```
STUDYxx アプリケーションの概要を教えてください。
オブジェクトの種類別の件数、主要なプログラムとファイル、全体の構造を説明してください。
```

**期待される動作**: スキル `understand-app-overview` と、ツール `understand_list_apps` / `understand_app_summary` が使われます。

> 🌟 **ポイント**: 設計書がなくても、**構造・主要オブジェクト・リスクの兆候**が一度に返ってきます。引き継ぎや新任者の立ち上がりを短縮できます。
>
> 🔎 **確認ポイント**: 多くのプログラムから使われているファイル（`TOKMSP` など）が「主要ファイル」として挙がっているか確認してください。

### 4.2 変更依頼の影響範囲を調べる

**場面**: 「`TOKMSP` に FAX 番号を追加したい」という依頼が届きました。どこまで影響しますか。

```
TOKMSP に項目（FAX番号）を追加する場合、影響を受けるオブジェクトを教えてください。
直接参照するものと、論理ファイル経由で間接的に参照するものを分けて、Mermaid 図でも示してください。
再コンパイルが必要なオブジェクトと、その推奨順序も教えてください。
```

**期待される動作**: スキル `understand-impact-analysis` と、ツール `understand_trace_dependencies` などが使われます。

> 🌟 **ポイント**: プログラムが `TOKMSP` を**直接**開いているケースと、論理ファイル（`TOKMSL01` / `TOKMSL02` / `TOKMSL03`）を**経由**して間接的に使っているケースを、**見落とさず**に切り分けて示します。再コンパイルの順序や、静的解析では見えない範囲（盲点）も併せて示されます。
>
> 💡 **従来の調べ方との違い**: 従来は、ソース内の検索と、コマンド（`DSPDBR` / `DSPPGMREF`）による調査を組み合わせて、手作業で突き合わせる必要がありました。

### 4.3 改修対象のプログラムを理解する

**場面**: 影響を受けるプログラムのうち、バッチ帳票の `BCH110` を改修することになりました。

```
BCH110 の役割、使用ファイル、呼び出し関係を説明してください。
```

**期待される動作**: スキル `understand-program-explainer` と、ツール `understand_describe_object` が使われます。

> 🌟 **ポイント**: 構成（OPM / ILE の別、使用ファイル、呼び出し元・呼び出し先）がすぐ分かり、**どこから手を付けるか**を判断できます。
>
> ⚠️ 処理の中身（計算ロジックなど）は、Understand ではなくソースから読み取ります。詳しく知りたい場合は、「`BCH110` のソースを読んで処理内容も説明してください」と追加で依頼します。

### 4.4 （オプション）システムの健康状態と整理対象を見る

**場面**: 影響調査のついでに、このシステムの「古さ」と「使われていない資産」も確認しておきたい。

```
STUDYxx について、次の観点で一覧にしてください。
1. OPM プログラム（ILE に変換されていないもの）
2. 動的 SQL を使っているオブジェクト
3. 他のどのオブジェクトからも使われていないオブジェクト（整理の候補）
```

**期待される動作**: ツール `understand_find_objects` などが使われ、条件に合うオブジェクトの一覧が返ります。

> 🌟 **ポイント**: モダナイゼーションの優先順位付けや、資産の整理候補の洗い出しに使えます。
>
> ⚠️ **「使われていない」は候補です。** メニューやジョブスケジューラーなど、**IBM i の外から**呼ばれるプログラム（バッチの入口など）も、スキャン上は「どこからも呼ばれていない」ように見えます。削除の判断は、運用担当者への確認を経て行ってください。

## 💡 このラボで学んだこと

### ✅ 影響範囲を「手作業で調べる」から「聞く」へ

| 観点 | 従来の調査（ソース検索・コマンド） | Understand |
|---|---|---|
| 準備 | 不要 | 最初に 1 回スキャンが必要 |
| 影響範囲の調べ方 | 質問のたびに、ソースやコマンド結果を手作業で突き合わせる | スキャン済みメタデータから即答 |
| 論理ファイル経由の間接参照 | 見落としやすい | 直接・間接を切り分けて提示 |
| 引き継ぎ・新任者 | 設計書か先輩に頼る | 構造を Bob に聞ける |
| 向く場面 | 単発の調査、処理ロジックの確認 | 繰り返しの影響分析、全体像の把握、棚卸し |

> 💡 **役割分担**: Understand は「**どこを見るべきか**」を素早く絞り込みます。「**中で何をしているか**」は、ソース（`read_member`）で確認します。両方を組み合わせるのが効果的です。

### ✅ Bob コインの節約（参考値）

Qiita 記事の事例では、**67 オブジェクトのライブラリーで、同様の分析の Bob コイン消費が 2.61 → 0.520（約 1/5）** に下がっています。事前スキャンしたメタデータを参照するため、AI が毎回オブジェクト情報を取りに行かずに済むことが理由と考えられます。

> ⚠️ これは記事の事例であり、このラボの環境で再現する数値ではありません。

### ⚠️ 静的解析の限界

- **動的呼び出し**（変数に入れたプログラム名を `CALL` する、など）と**動的 SQL** は見えません（動的 SQL を使うオブジェクトは、要確認として示されます）
- **ソースは読みません。** ソースとコンパイル済みオブジェクトが食い違っている場合、結果はオブジェクトを反映します
- スキャン後に変更したオブジェクトは、再スキャンするまで反映されません。変更したライブラリーだけを、Libraries タブから再スキャンすることもできます

## 🎯 よくある質問

**Q: Understand ボタンや Set install library が表示されない**

A: Bob を再起動してください。それでも出ない場合は、PP4i が v2.0.0 であることを確認してください。

**Q: Install Understand で権限エラーになる**

A: `UNDxx` に対する作成権限がありません。講師に依頼してください。

**Q: `Q` で始まるライブラリーをスキャンしたい**

A: スキャン対象外です。`CPYLIB` で別名のライブラリーに複製してください（LAB1 と同じ方法）。

**Q: 影響を受けるプログラムが想定より少ない（多い）**

A: 実機にコンパイル済みのオブジェクトがあるものだけが対象です。ステップ0 の集計結果と照らし合わせてください。
