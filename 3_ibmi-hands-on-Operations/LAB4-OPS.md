# LAB4-OPS: 毎朝の稼働チェックを定型化（オプション） 🔁

## 🎯 このラボの目標

LAB1〜3 で会話しながら実施したチェックを、**誰が実行しても同じ結果になる「定型業務」**にします。プロンプトテンプレートをファイルとして管理し、毎朝ワンアクションで稼働チェックレポートを作れるようにします。

**所要時間**: 10分
**難易度**: ★★☆☆☆（初中級）
**使用モード**: IBM i Developer モード
**ワークスペース**: Local

---

## ステップ1: テンプレートを確認する（2分)

[`prompts/毎朝の稼働チェック.md`](./prompts/毎朝の稼働チェック.md) を開いてください。

- `{{ }}` の部分が環境ごとに書き換える箇所です
- 自分の番号に合わせて `{{STUDYxx}}` と `{{STUDYxx/OPSMSGQ}}` を書き換えて保存してください

> 💡 **ポイント**: プロンプトを**ファイルとして管理**することで、
> - 担当者によってチェック内容がぶれない
> - Git で変更履歴を管理できる（「いつからこの項目をチェックしているか」が分かる）
> - 運用手順書そのものとしてレビューできる

---

## ステップ2: 状態を壊してからチェックを実行する（4分）

LAB3 ですべて復旧済みなので、接続先実機で再度セットアッププログラムを実行して障害状態を再現します。

```
接続先 IBM i で次の CL コマンドを実行してください（xx は自分の番号）：
CALL PGM(HANDSON/OPSSETUP) PARM('xx')
```

数秒待ってから、チャット欄でプロンプトテンプレートを指定して実行します。

```
@prompts/毎朝の稼働チェック.md を実行してください。
```

**期待される動作**:
1. Bob がテンプレートに記述されたチェック項目に従い、PP4i の `execute_sql_statement` で実機状態を順番に問い合わせます。
2. `OPSxxB`＝停止、`OPSxxC`＝応答待ち、`OPSNIGHT`＝スケジュール保留 などを検知します。
3. **安全ルールに基づき対処は勝手に実行せず**、事象・原因・対処コマンド案・エスカレーション先を構造化して整理します。
4. `docs/稼働チェック_YYYYMMDD.md` が作成・保存されます。

> ✅ **確認**: レポートの先頭に「要対応 n 件」と表示され、付録に使用した IBM i Services SQL が載っていることを確認してください。

---

## ステップ3: 自社の運用ルールに育てる（4分）

レポートを見て「この項目も毎朝見たい」「この表現は分かりにくい」と感じた点を、Bob に依頼してテンプレートに反映させます。

**依頼例**:

```
prompts/毎朝の稼働チェック.md に以下のチェック項目を追加してください。
- 出力待ち行列 QPRINT に 100 件以上のスプールが溜まっていないか
- 前回のチェックから新たに *SECADM 特殊権限を持ったユーザーがいないか
```

```
.bob/rules/ops-safety.md に以下のルールを追加してください。
- 応答待ちメッセージに応答する場合は、必ずメッセージの2次レベルテキストを表示してから提案すること
```

> 💡 **Rules とテンプレートの使い分け**
>
> | | Rules（`.bob/rules/`） | プロンプトテンプレート（`prompts/`） |
> |---|---|---|
> | いつ効く？ | **常に**（すべての会話） | **呼び出したときだけ** |
> | 書く内容 | 守るべき約束（禁止事項・承認ルール・表現の統一） | 定型作業の手順（何をどの順で確認するか） |
> | 例 | 「ENDSBS は実行しない」 | 「毎朝この6項目をチェックする」 |

## 💡 このラボで学んだこと

✅ **会話でやったことを「資産」として残せる**
- プロンプトテンプレート＝実行可能な運用手順書

✅ **お客様環境での次のステップ**
1. 既存の運用手順書（Excel・紙）から `EXPECTED_JOBS` を作る
2. 毎朝の確認項目をテンプレート化する
3. 障害対応記録を `docs/` に溜め、Bob に「過去の類似障害」を検索させる
4. 慣れてきたら、IBM i 側でチェック SQL を定期実行し、Bob は「異常時の調査と対処案作成」に専念させる
