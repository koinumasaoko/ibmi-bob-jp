## 1. 環境構成

```
IBM i（検証区画・ハンズオン専用区画）
├── HANDSON ライブラリー（講師が作成）
│   ├── QCLSRC        OPSWORK / OPSSETUP / OPSENV のソース
│   ├── OPSWORK  *PGM  業務ジョブ模擬（RUN / NEEDFILE / ASK）
│   ├── OPSSETUP *PGM  参加者ごとのジョブ投入・リセット
│   ├── OPSENV   *PGM  環境構築（講師が1回だけ実行）
│   ├── HANDSON  *SBSD ハンズオン用サブシステム
│   ├── HANDSON  *CLS
│   └── HANDSONQ *JOBQ
├── ジョブ・スケジュール項目 OPSNIGHT（保留中）
└── STUDY01〜STUDYnn ライブラリー（QEOL の複製・参加者ごと）
    ├── （QEOL のソース・オブジェクト一式）
    ├── OPSMSGQ  *MSGQ  OPSSETUP が作成
    └── EXPECTED_JOBS / RECVFILE / PGMREF  参加者が LAB 中に作成
```

### 各参加者のジョブの仕掛け

| ジョブ | モード | 挙動 | LAB での役割 |
|-------|-------|------|------------|
| `OPSxxA` | RUN | 30秒ごとに `DLYJOB` で常駐 | 正常なジョブ |
| `OPSxxB` | NEEDFILE | `STUDYxx/RECVFILE` が無いため、メッセージを残して**数秒で終了**（CPF1241＝正常終了） | **停止**ジョブ。終了コードだけでは気づけない点が教材の肝 |
| `OPSxxC` | ASK | `STUDYxx/OPSMSGQ` に照会メッセージを送り **MSGW** | **応答待ち**ジョブ |

## 2. 事前準備（前日まで）

### 2.1 前提条件

- [ ] IBM i 7.4 以降（7.4 は SF99704 レベル 13 以上）、IBM i Services の最新 PTF グループ（SF99xxx DB2 グループ）適用済み
  - 使用する主なサービス：`OBJECT_STATISTICS`、`SYSPARTITIONSTAT`、`SUBSYSTEM_INFO`、`AUTOSTART_JOB_INFO`、`ACTIVE_JOB_INFO`、`MESSAGE_QUEUE_INFO`、`SCHEDULED_JOB_INFO`、`HISTORY_LOG_INFO`、`JOBLOG_INFO`、`SYSTEM_STATUS_INFO`
- [ ] SSH デーモン起動（`STRTCPSVR *SSHD`）、5733-SC1 導入済み、`QSSHD` 有効
- [ ] 参加者の PC に Bob IDE + PP4i 導入済み・シート割り当て済み

### 2.2 HANDSON ライブラリーとプログラムの作成

講師ユーザー（`*ALLOBJ`・`*JOBCTL` 保有）で実行します。ソースは [`instructor/src/`](./src/) にあります。Bob に「`instructor/src` の3本を HANDSON/QCLSRC にアップロードしてコンパイルして」と依頼しても構いません。

```cl
CRTLIB LIB(HANDSON) TEXT('運用編ハンズオン')
CRTSRCPF FILE(HANDSON/QCLSRC) RCDLEN(112) CCSID(5035)
/* OPSWORK / OPSSETUP / OPSENV を QCLSRC にアップロード（メンバータイプ CLLE） */
CRTBNDCL PGM(HANDSON/OPSWORK)  SRCFILE(HANDSON/QCLSRC)
CRTBNDCL PGM(HANDSON/OPSSETUP) SRCFILE(HANDSON/QCLSRC)
CRTBNDCL PGM(HANDSON/OPSENV)   SRCFILE(HANDSON/QCLSRC)
CALL PGM(HANDSON/OPSENV)
```

> ⚠️ **CCSID**: ソースに日本語メッセージを含むため、ソース物理ファイルは日本語 CCSID（5035 または 1399）で作成してください。

### 2.3 参加者ユーザーと作業ライブラリー

```cl
/* 参加者ごとに繰り返す（01 → nn） */
CRTUSRPRF USRPRF(STUDY01) PASSWORD(xxxxxxxx) USRCLS(*USER) +
          SPCAUT(*NONE) INLPGM(*NONE) TEXT('運用編ハンズオン 参加者01')
CPYLIB FROMLIB(QEOL) TOLIB(STUDY01) CRTLIB(*YES)
CHGOBJOWN OBJ(STUDY01) OBJTYPE(*LIB) NEWOWN(STUDY01)
```

> 💡 **権限設計の意図**: 参加者は `*JOBCTL` を持たないため、**自分が投入したジョブ以外は操作できません**。他の参加者や システムジョブを誤って止める事故を防ぎます。

### 2.4 動作確認（必ず実施）

参加者ユーザー `STUDY01` でサインオンして、以下を確認します。

```cl
CALL PGM(HANDSON/OPSSETUP) PARM('01')
/* 10 秒ほど待つ */
WRKACTJOB SBS(HANDSON)          /* OPS01A=DLYW, OPS01C=MSGW, OPS01B はいない */
DSPMSG MSGQ(STUDY01/OPSMSGQ)    /* RECVFILE 未存在メッセージ と 照会メッセージ */
```

続いて、参加者権限で IBM i Services が期待どおりに見えるかを確認します。

```sql
SELECT * FROM QSYS2.SUBSYSTEM_INFO;
SELECT * FROM TABLE(QSYS2.ACTIVE_JOB_INFO(SUBSYSTEM_LIST_FILTER => 'HANDSON', DETAILED_INFO => 'NONE')) X;
SELECT * FROM QSYS2.SCHEDULED_JOB_INFO;
SELECT * FROM TABLE(QSYS2.HISTORY_LOG_INFO(START_TIME => CURRENT TIMESTAMP - 1 HOUR)) X;
```

> ⚠️ **権限による見え方の差**: `*JOBCTL` 等の特殊権限が無いユーザーでは、一部のサービスで他ユーザーのジョブ情報やスケジュール項目の詳細が返らない場合があります。上記で `OPSNIGHT` やヒストリーログが見えない場合は、参加者ユーザーに `*JOBCTL` を付与するか、該当ステップを講師デモに切り替えてください（`*JOBCTL` を付与する場合は、Rules による制御がより重要になる旨を参加者に説明します）。

最後に、PP4i から一連の LAB を**通しで1回**実施し、Bob の応答を確認しておきます（Bob の出力は毎回同じではないため、想定外の SQL を組んだ場合の誘導方法を把握しておく）。

- LAB1-OPS はステップ1 と ステップ4 だけ実施（ステップ2・3 は講師デモ）

- LAB4-OPS は持ち帰り課題

- LAB4-OPS を実施

## 4. よくあるトラブルと対処

| 症状 | 原因 | 対処 |
|-----|------|------|
| `OPSSETUP` が CPF9898「作業ライブラリーがありません」 | `xx` の置き換え忘れ | `PARM('01')` のように番号を指定し直す |
| `OPSxxA/C` も一覧に出ない | `HANDSON` サブシステム未開始、またはジョブ待ち行列が保留 | 講師が `STRSBS HANDSON/HANDSON`、`RLSJOBQ HANDSON/HANDSONQ` |
| `OPSxxC` が MSGW にならず終了している | 照会メッセージに既定値で自動応答された | `SBMJOB` の `INQMSGRPY(*RQD)` を確認。システム応答リストに該当エントリーがないか確認 |
| Bob が `ACTIVE_JOB_INFO` を全件取得して遅い | 絞り込みなし | 「SUBSYSTEM_LIST_FILTER で HANDSON に絞って」と追加指示（Rules に記載済み） |
| Bob が存在しない列名を使って SQL エラー | LLM の推測 | 「RAG で IBM i ドキュメントを確認してから SQL を直して」と指示。答え合わせ用に `sql/` を参照 |
| Bob が承認を求めずに CL を実行した | Bob の自動承認設定が有効 | Bob の設定で「コマンド実行の自動承認」をオフにする（**ハンズオン前に全員の設定を確認**） |
| 禁止コマンドを Bob が実行しようとした | Rules が読み込まれていない | `3_ibmi-hands-on-Operations` フォルダーを**ルートとして**開いているか確認 |
| `OPSxxB` を再投入してもすぐ止まる | `RECVFILE` を別ライブラリーに作成した | `STUDYxx` に作られているか確認 |
| やり直したい | — | `CALL HANDSON/OPSSETUP PARM('xx')` で初期状態に戻る（`EXPECTED_JOBS` は残る） |

## 6. お客様環境での実施に向けたヒアリング項目

ハンズオン後の提案（本番運用への展開）に向けて、以下を確認しておくと次の打ち手につながります。

- 現在の運用手順書の形式（Excel／紙／ジョブスケジューラー製品）と、常駐ジョブ・夜間バッチの本数
- 朝の稼働確認にかかっている時間と担当人数
- 障害一次対応の体制（夜間・休日の連絡フロー）と、エスカレーション先
- 運用担当者の権限（`*JOBCTL` 保有者の範囲）
- 運用部門と開発部門の役割分担（運用カード・設計書を誰が作り、誰が維持するか）
