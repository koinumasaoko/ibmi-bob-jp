# 毎朝の稼働チェック（プロンプトテンプレート）

> 使い方：`{{ }}` の部分を自社環境に合わせて書き換え、Bob のチャットに `@prompts/毎朝の稼働チェック.md を実行してください` と入力します。
> このテンプレートは**参照のみ**です。対処が必要な場合も、実行はせず対処案の提示までにとどめます。

---

IBM i の朝の稼働チェックを実施してください。対処はせず、確認と報告のみ行ってください。

## チェック項目

1. **サブシステム**
   - 次のサブシステムが `ACTIVE` であること：{{QBATCH, QINTER, QUSRWRK, HANDSON}}

2. **常駐ジョブ**
   - `{{STUDYxx}}.EXPECTED_JOBS` に定義されたジョブと、アクティブジョブを突き合わせる
   - 判定：停止／応答待ち（MSGW）／稼働中

3. **応答待ちメッセージ**
   - メッセージ待ち行列 `{{STUDYxx/OPSMSGQ}}`（本番では `QSYS/QSYSOPR`）の未回答の照会メッセージ

4. **夜間バッチの結果**
   - 前日 {{18:00}} 以降のヒストリーログから、異常終了したジョブ（メッセージ ID `CPF1164`）を抽出
   - 正常終了（`CPF1241`）でも、ジョブログやメッセージ待ち行列に「中止」「エラー」等のメッセージを残しているジョブがあれば併せて報告

5. **ジョブスケジュール**
   - 状況が `HELD`（保留）のスケジュール項目

6. **システム資源**（参考）
   - システム ASP 使用率（`QSYS2.SYSTEM_STATUS_INFO`）が {{80}}% を超えていないか

## 出力

- `docs/稼働チェック_YYYYMMDD.md` に保存（YYYYMMDD は今日の日付）
- 先頭に **「異常なし」または「要対応 n 件」** を大きく表示
- 要対応事項は `EXPECTED_JOBS.PRIORITY` の順（A → B）に並べ、それぞれに
  - 事象
  - 推定原因（根拠となるメッセージ ID と本文）
  - 対処案（コマンド案。**実行はしない**）
  - エスカレーション先（`EXPECTED_JOBS.CONTACT`）
  を記載する
- 最後に、使用した SQL をすべて付録として載せる（Bob がいなくても再実行できるように）
