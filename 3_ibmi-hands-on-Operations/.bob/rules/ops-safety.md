# IBM i 運用作業 安全ルール

## 概要
このプロジェクトでは、IBM Bob を IBM i の**運用業務**（稼働確認・障害一次対応・資産把握）に使用します。
対象は本番相当のシステムであるという前提で、以下のルールを必ず守ってください。

## 1. 参照系と更新系の区別

### 1.1 参照系（承認なしで提案・実行してよい）
- `SELECT` 文（IBM i Services: `QSYS2.*`、`SYSTOOLS.*`、カタログビュー等）
- 表示系 CL コマンド：`DSPxxx`、`WRKxxx` の出力ファイル指定、`RTVxxx`
- `DSPPGMREF`、`DSPOBJD`、`DSPFD` で `OUTPUT(*OUTFILE)` を指定し、**ユーザー自身の作業ライブラリー（STUDYxx）** に出力する場合

### 1.2 更新系（実行前に必ず提示し、ユーザーの承認を得る）
- `INSERT` / `UPDATE` / `DELETE` / `CREATE` / `DROP` 等の SQL
- ジョブ・メッセージを操作する CL コマンド：`SBMJOB`、`ENDJOB`、`HLDJOB`、`RLSJOB`、`SNDRPY`、`CHGJOB`
- プログラムの呼び出し：`CALL`
- オブジェクトの作成・削除：`CRTxxx`、`DLTxxx`（作業ライブラリー `STUDYxx` 内に限る）
- 実行前に次の3点を日本語で説明すること
  1. 実行するコマンド（完全な形）
  2. 期待される結果
  3. 影響範囲（どのジョブ・どのオブジェクトに影響するか）

### 1.3 禁止（ユーザーに依頼されても実行しない）
- `PWRDWNSYS`、`ENDSYS`、`ENDSBS`、`STRSBS`、`ENDTCPSVR`、`ENDHOSTSVR`
- `CLRLIB`、`DLTLIB`、`CLRPFM`、`RSTxxx`、`SAVxxx`
- 他ユーザーが所有するジョブへの `ENDJOB` / `HLDJOB`
- `QSYS`、`QGPL`、`QUSRSYS` 等のシステムライブラリー配下のオブジェクトの作成・変更・削除
- システム値・ネットワーク属性の変更（`CHGSYSVAL`、`CHGNETA` 等）

禁止事項に該当する依頼を受けた場合は、実行せずに「運用ルールにより実行できない」旨と理由を説明し、
代替手段（例：システム管理者への依頼内容の文案）を提示してください。

## 2. ハンズオン環境の範囲
- 起動・停止・応答の操作対象は、**サブシステム `HANDSON` 内の、ユーザー自身のジョブ（`OPSxx*`）のみ**とする
- オブジェクトの作成先は**ユーザー自身の作業ライブラリー `STUDYxx`** のみとする

## 3. SQL の書き方
- IBM i Services を使う場合は、まず `DETAILED_INFO => 'NONE'` などの軽量オプションを優先する
- `ACTIVE_JOB_INFO` を全件取得しない。`SUBSYSTEM_LIST_FILTER`、`JOB_NAME_FILTER` 等で絞り込むこと
- 結果が多い場合は `FETCH FIRST n ROWS ONLY` で件数を制限すること
- IBM i Services の列名・パラメーターに自信がない場合は、推測せず RAG で IBM i ドキュメントを確認すること

## 4. 回答の書き方
- 結果は表形式で示し、最後に「運用者として注意すべき点」を1〜3行で添える
- ジョブの状況は以下の表現に統一する
  - 稼働中（RUN / DLYW / EVTW / DEQW 等）
  - **応答待ち**（MSGW）← 要対応
  - **停止**（アクティブジョブに存在しない）← 要対応
- レポートをファイルに保存する場合は、ローカルの `docs/` フォルダーに保存する

## 5. 障害対応の進め方
障害（停止・応答待ち）を検知した場合は、以下の順で進めること。いきなり再起動を提案しない。
1. **事実確認**：どのジョブが、いつから、どの状態か
2. **原因調査**：ヒストリーログ（`QSYS2.HISTORY_LOG_INFO`）、メッセージキュー（`QSYS2.MESSAGE_QUEUE_INFO`）を確認
3. **対処案の提示**：コマンドと影響範囲を説明し、承認を得る
4. **実行と再確認**：実行後、再度稼働状況を確認して結果を報告
5. **記録**：対応内容を `docs/` に障害対応記録として残す
